# Stepwise

사용자가 입력한 Python 코드를 실제로 실행하고, **알고리즘 패턴과 자료구조의 쓰임에 맞춰 실행 과정을 시각화**하는 다크 테마 웹 앱입니다.

**[Stepwise 바로 사용하기 →](https://dang0321.github.io/stepwise/)**

## 사용 방법

1. 예제를 고르거나 **수정**을 눌러 코드를 입력합니다.
2. **샘플 입력**에서 기본·경계 사례를 미리 보고 **이 샘플을 입력창에 적용**합니다. 직접 작성한 코드는 **내 코드에서 제안 받기**로 입력 후보를 요청할 수 있습니다.
3. **시각화 실행**으로 기록을 수집합니다. 처음에는 Pyodide 실행 환경을 다운로드합니다.
4. 추천된 알고리즘 유형과 근거를 보고, **다음 줄**, 이전 단계, 재생·정지·속도(0.25×–4×), 타임라인으로 탐색합니다.
5. 변수나 관련 자료구조를 눌러 대상을 바꾸고, 필요하면 **표시 방식**을 직접 선택합니다. **자동 추적으로**를 누르면 추천 대상 선택으로 돌아갑니다.

`← / →`는 단계 이동, `Space`는 재생/일시정지입니다. 코드 편집 중에는 `Tab`으로 공백 4개, `Ctrl + Enter`로 실행합니다.

**강조된 줄은 다음 실행할 줄이고, 변수는 그 줄 실행 전의 상태입니다.** 원래 코드의 주석, 실제 대입식·조건식, 현재 값으로 계산 가능한 조건의 참/거짓, 직전 단계와의 차이를 함께 표시합니다. 파란색은 읽기, 노란색은 쓰기 대상으로 분석한 위치이며, 녹색은 직전 기록에서 바뀐 값입니다. 접근 위치는 해당 줄 실행 전의 인덱스로 계산합니다. 한 줄 안에서 함수 호출이 값을 바꾸는 복합 표현식은 실제 접근과 다를 수 있습니다.

함수 반환은 별도 단계이며 마지막 단계는 실행 완료입니다. 일시정지는 기록 재생을 멈추고, 기록 수집 중 중단은 Worker를 종료합니다.

## 적절한 샘플 입력

샘플을 두 종류로 구분합니다.

- **실행 검증한 예제**: 현재 코드가 내장 예제와 일치할 때 제공하며 예상 출력도 볼 수 있습니다. 알고리즘별로 이미 정렬된 배열, 중복·음수, 탐색 실패, 도달 불가, 사이클, 정점 하나 등 의미가 다른 분기를 구성했습니다.
- **입력 형식 추정**: 사용자 코드의 AST에서 읽기 순서, 반복 횟수, 배열 길이, 격자 행·열, 간선 구조를 추정해 기본/작은 크기 후보를 만듭니다. 중간 인덱스 계산이 있으면 정렬된 수열을, 문자 비교가 있으면 비교에 쓰인 문자 집합을 참고합니다. **문제 원문과 제약을 알 수 없으므로 정답이나 입력의 적합성을 보장하지 않습니다.**

분석은 사용자 코드를 실행하지 않습니다. 적용 버튼을 누를 때만 입력창을 바꾸며 자동 실행하지 않습니다. 코드를 바꾸면 이전 코드에서 만든 제안을 사용하지 않습니다.

자동 제안은 `int(input())`, 공백으로 나눈 숫자 배열, `range` 반복 입력, 2차원 입력, 여러 테스트 케이스, `sys.stdin.readline` 및 별칭을 중심으로 지원합니다. 조건·함수·while 내부 입력, 전체 토큰 파서, 사용자 정의 구분자 등 구조를 확정하기 어려운 경우에는 이유를 표시하고 생성을 보류합니다. [지원 범위와 후속 과제](COVERAGE.md)를 참고하세요.

`input()`, `sys.stdin.readline()`, `sys.stdin.read()`, `sys.stdin.buffer.readline()`를 통한 **실제 실행**은 지원합니다. 자동 샘플 생성 범위와는 다릅니다. 입력을 미리 넣는 방식이고, 빈 줄과 마지막 줄바꿈 유무를 보존합니다.

## 알고리즘 분석과 시각화

현재 **22개 예제, 21개 분석 패턴**을 다룹니다. 패턴 수에는 큐·스택·격자·재귀 같은 공통 연산도 포함하며, 서로 다른 알고리즘 21개의 모든 구현을 인식한다는 의미는 아닙니다.

| 분야        | 예제 및 분석 대상                    | 제공하는 보기                                    |
| ----------- | ------------------------------------ | ------------------------------------------------ |
| 정렬·탐색   | 버블/삽입 정렬, 이진 탐색, 투 포인터 | 양수·음수 막대, 경계·중간 인덱스, 읽기/쓰기 위치 |
| 구간 처리   | 누적 합, 슬라이딩 윈도우             | 누적값 테이블, 접근 위치, 관련 누적 변수         |
| 그래프      | BFS, DFS, 다익스트라, 위상 정렬      | 방향·가중 그래프, 현재 정점, 큐·힙·거리 배열     |
| 집합        | 유니온 파인드                        | 부모를 가리키는 화살표, 대표 정점                |
| DP          | 피보나치, 0–1 배낭                   | 이전 상태와 갱신 위치를 구분한 테이블            |
| 재귀·선택   | 팩토리얼, 조합 백트래킹              | 호출 스택, 함수별 지역 변수, 선택 스택           |
| 자료구조    | 힙, 괄호 스택, 큐, 빈도 집계         | 이진 힙 트리, TOP/FRONT/BACK, 빈도 막대          |
| 문자열·비트 | KMP, 비트마스크 부분집합             | 문자 인덱스, 실패 함수 테이블, 비트 표시         |
| 격자        | 2차원 순회, 격자 BFS                 | 행·열 셀, 다음 참조/갱신 위치                    |

추천은 예제 ID나 `i/j/node` 같은 고정 변수 이름 대신 **실제 코드의 구문·연산·인덱스 관계**를 근거로 만듭니다. 함수 범위도 구분합니다. 근거와 관련 코드 줄을 화면에서 확인할 수 있고 수동 보기로 바꿀 수 있습니다.

숫자 배열의 눈금은 실행 기록 전체에 고정되어 음수와 크기 변화를 일관되게 비교할 수 있습니다. 그래프는 인접 리스트/딕셔너리와 `(이웃, 가중치)` 형태를 지원합니다. 24개가 넘는 정점, 31개가 넘는 힙 원소, 해석 불가능한 구조는 값으로 표시합니다. 부모 트리는 고정된 원형 배치에서 연결 관계를 보여줍니다. 객체 기반 일반 트리를 자동 배치하는 기능은 아닙니다.

## 사용자 코드에 대한 추천 과정

1. **코드의 사용 방식**에서 컨테이너 역할을 찾습니다. 고정 변수 이름이 아니라 인덱스·반복·라이브러리 연산을 사용합니다.
2. **실행 중 같은 객체인지** 확인해 함수 인자, 반환된 컨테이너, 별칭 변수에 역할을 연결합니다. 값만 같은 복사본은 연결하지 않으며, 별칭을 새 값에 다시 대입하면 연결이 끊깁니다. 최근 64개 컨테이너까지 역할 정보를 보존합니다.
3. **현재 직렬화된 값의 구조**가 해당 보기에 맞는지 확인합니다. 그래프 연결 형식, 부모 인덱스 범위, 비트의 정수 조건, 표시 개수 등을 확인하고, 맞지 않으면 이유와 함께 일반 보기로 전환합니다. 이는 구조 확인이며 정렬·힙 불변식이나 알고리즘 정답을 증명하지 않습니다.
4. **현재 범위의 실제 접근**을 강조합니다. 별칭에도 같은 칸을 표시하고, 전역 변수와 함수의 같은 이름을 구분합니다. `and/or`, 조건식, 연쇄 비교에서 건너뛰는 접근은 제외합니다. 부작용을 확정할 수 없는 호출 뒤의 접근과 comprehension 내부 인덱스는 추측하지 않습니다.

그래프에서는 이웃이 다른 배열의 인덱스로 사용되는 관계를 찾아 거리·방문 상태 등의 현재 값을 정점 아래에 표시합니다. 이웃/가중치의 튜플 순서는 코드에 충분한 단서가 있을 때 구분합니다. 단서가 부족하면 기본 순서 `(이웃, 가중치)`로 해석하므로 원본 값과 함께 확인해야 합니다. `{정점: {이웃: 가중치}}` 형태와 딕셔너리에서 키가 생략된 끝 정점도 지원합니다.

예를 들어 아래 코드를 직접 붙여 넣으면 `bucket`, `data`, `alias`가 같은 리스트라는 사실을 이용해 힙 보기를 연결합니다.

```python
import heapq

data = [4, 2, 3]
alias = data

def prepare(bucket):
    heapq.heapify(bucket)

prepare(data)
print(alias)
```

다음 실행·주석은 시각화 스크롤과 분리된 전용 패널에 표시하며, 메인 대시보드와 하단 실행바의 고정 배치를 유지합니다.

## 실행 방식과 한계

React + TypeScript + Vinext/Vite 정적 사이트입니다. Pyodide 314.0.6의 Python을 모듈 Web Worker에서 실행하고 `sys.settrace`로 기록합니다. 예제 전용 애니메이션이 아니라 실제 실행 결과입니다.

코드를 업로드하는 서버나 분석 수집 기능은 구현하지 않았습니다. 런타임 다운로드에는 인터넷이 필요합니다. 사용자 코드가 직접 네트워크 기능을 호출하는 경우는 별개입니다. Worker는 실행마다 새로 생성하지만 악성 코드용 보안 샌드박스는 아닙니다.

- 최대 1,200단계, 추적 중 8초 검사 + 메인 스레드의 12초 강제 종료
- 실행 환경 다운로드 최대 90초, 코드 30,000자, 입력 50,000자
- 출력 16,000자, 기록 약 600만 문자 제한
- 컨테이너 80개, 범위별 변수 40개, 깊이 4, 단계당 값 600개까지 표시하며 생략 알림 제공
- 기본 Python/표준 라이브러리 중심. 별도 pip 패키지 설치 UI 없음
- 사용자 클래스는 타입 요약. 메모리 주소와 객체 내부를 완전하게 표시하지 않음. 별칭 연결은 지원하는 기본 컨테이너 범위
- 스레드·비동기·동적 exec·추적기를 변경하는 코드는 완전하게 추적하지 않음
- 복합 문장과 comprehension은 Python trace event에 따라 한 줄에서 여러 단계가 나올 수 있음
- 되돌리기는 실행 기록 재생. 실제 실행의 역연산은 아님
- 알고리즘 추천은 AST 규칙과 실행 중 객체 관계를 이용한 추정. 문제 의도나 코드 정당성 증명, 모든 구현에 대한 최적 시각화 보장은 아님
- 코드와 입력은 새로고침하면 초기화됨

## 로컬 실행과 검증

Node.js 24 이상과 npm이 필요합니다. Python을 별도로 설치하지 않아도 사이트와 WASM 테스트를 실행할 수 있습니다.

```powershell
npm ci
npm run dev
```

기본 개발 주소는 http://localhost:3000/ 입니다.

```powershell
npm run typecheck
npm test
npm run build
npm start
```

정적 결과물은 `dist/client/`, 미리보기는 http://127.0.0.1:4173/ 입니다.

`npm test`는 Pyodide WASM에서 **80개 Python 테스트**, **22개 예제의 기본·경계 62건 및 이름 변경 22건, 총 84개 실행 시나리오와 예상 출력**, **기존 시각화 모델 검증 19건과 사용자 코드 보기 검증 18건**, 값 표현 검증을 실행합니다. 입력 개수와 행·열 일치, 위험한 식 재평가 방지, 범위 혼동·오탐, 음수 인덱스, 가중 간선, 수동 표시 선택 등을 확인합니다. Python이 설치되어 있다면 다음으로 Python 테스트만 실행할 수도 있습니다.

```powershell
$env:PYTHONPATH='public'
python -B -m unittest discover -s tests
```

브라우저 버튼 클릭·모바일 화면·실제 브라우저 CDN 다운로드를 포함한 E2E/시각 QA는 아직 수행하지 않았습니다. 선택적 WebMCP 읽기/단계 이동 도구도 해당 브라우저 환경에서는 미검증입니다.

Windows에서 기본 Vinext CLI의 즉시 종료가 libuv assertion을 발생시켜 `scripts/build.mjs`는 Vite build API와 Vinext prerender API를 순서대로 사용합니다. 빌드/렌더 오류는 그대로 실패합니다.

## GitHub Pages로 공유하기

**[사이트 바로가기](https://dang0321.github.io/stepwise/)** · [GitHub 저장소](https://github.com/dang0321/stepwise)

Pages 게시 원본은 `main` 브랜치의 `/docs`입니다.

```powershell
$env:PAGES_BASE_PATH='/stepwise'
npm run build
Get-ChildItem -LiteralPath dist/client/stepwise -Force | Copy-Item -Destination docs -Recurse -Force
Remove-Item Env:PAGES_BASE_PATH
```

하위 경로 빌드 결과인 `dist/client/stepwise`의 내용 전체와 `.nojekyll`을 배포합니다. `사용자명.github.io` 루트 저장소는 `PAGES_BASE_PATH`를 생략하고 `dist/client`를 사용합니다. 소스와 `docs/`를 함께 커밋해 `main`에 푸시하면 새 스냅샷을 게시합니다.

- `lib/examples.ts`, `lib/extra-examples.ts`, `lib/example-cases.ts`: 예제와 예상 출력
- `tests/`: 추적·분석·입력·시각화 모델 회귀 검증
- [COVERAGE.md](COVERAGE.md): 지원 근거, 예제, 확장 우선순위
